# 小型モデル (蒸留) と kana-whisper の比較 (合成音声、2026-09-17)

同じ評価 (`scripts/eval_synthetic.py --n 60`、首都国道 100 台、雑音混合 180 発話 + 文法外 16 + PTZ 24 + 確認 18 + 電話応対 10) を、ASR だけ差し替えて実行。
蒸留: ReazonSpeech small (95h) に kana-whisper の疑似ラベル → whisper-small の decoder を先頭+最終の 2 層に切り CE で 3 epoch (`openvons/voice/distill/`)。

| | kana-whisper (809M) | 蒸留 small 2 層 (147M) |
|---|---|---|
| パラメータ | 809M | 147M |
| 自由認識の最近傍 (A) | 0.939 | 0.956 |
| 候補採点・既定校正 (B) | 0.939 | 0.811 |
| 校正後 argmax (該当なし含む) | 0.980 | 0.842 |
| ECE 校正後 | 0.007 | 0.117 |
| 全国 2,932 台 校正後 | 0.961 | 0.833 |
| 文法外の棄却 | 1.00 | 1.00 |
| PTZ (FOCUS) | 1.000 | 0.583 |
| はい/いいえ (CONFIRM, SNR10) | 0.944 | 0.556 |
| 確認待ちで電話の「はい」を棄却 | 1.00 | 1.00 |
| 遅延 中央値 (encoder / 自由認識 / 採点) | 223ms (30 / 136 / 49) | 184ms (12 / 123 / 36) |

## 読み取り
- 自由認識 (最近傍) はほぼ同等。候補の尤度採点が弱く、短い命令 (PTZ、はい/いいえ) で崩れる。2 層 decoder の対数尤度が候補間の差を付けられていない。
- 表の遅延は評価中に同じ GPU で別の学習が走っており (使用率 94%)、両方とも 3〜4 倍遅く出ている。空いている GPU で同じ 12 発話を測り直すと
  kana-whisper 44ms / 蒸留 small 32ms (encoder + 自由認識 + 16 候補の採点、中央値)。生成トークン数は 8.8 と 8.4 で同等 (EOT は正常に出ている)。
  小型化の遅延の恩恵が薄いのは GPU では Python 側のオーバーヘッドが支配的なため。端末 (WebGPU/WASM) では encoder の計算量差 (約 5 倍) が効く。
- 次の手: ReazonSpeech medium (1,000h) で学習量 10 倍、decoder 4 層、教師分布の KL 蒸留、疑似ラベルの反復ハルシネーション除去。
- 目的は端末内推論なので、精度は候補採点方式の寛容さに頼れる範囲 (自由認識 0.95) にはある。尤度の質を上げるのが本丸。
