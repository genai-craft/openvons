画像は docs/jevpick/img/ (1200x675)。1/4 に 01_hero.png、2/4 に 04_accuracy.png、3/4 に 03_long_context.png、4/4 は画像なし (URL カード)。単発には 02_methods.png。

## 4 連スレッド (本命)

**1/4** (278)
```
AIに「書かせず、選ばせる」openvonsの考え方を、AIが文章を書く速さそのものに使ってみました。JevPick。

次の数語の候補を並べ、モデル自身の内部状態で1つ選び、まとめて検算する。
ツール呼び出しで3〜5倍速。出力は1文字も変わりません。予測モデルの学習も不要です。
https://openvons.com/jevpick
```

**2/4** (208)
```
なぜ速くなるか。

エージェントが出す関数呼び出しは形が決まっています。ツール定義から機械的に作った候補の中に、正解の続きが90%入っていました。

あとは「選ぶ精度」だけ。単純な頻度順は64%、JevPickは88%当てます。
```

**3/4** (229)
```
意外だった発見。

いま流行りの先読み手法(DFlash)は、300語の文脈では5.4倍速。ところが16k語の長い文脈では1.0倍、効果が消えます。n-gram方式は0.7倍と逆に遅い。

長文脈で効くのは予測器の賢さではなく「いま先読みすべきか」の判断でした。
```

**4/4** (245)
```
おまけ。Qwen3.5系に同梱のMTPは、ツール呼び出しで次の語を99.7%当てます。4-bitの27Bで6倍、Qwen3.8-Flash-Nextで5.8倍。エージェント用途なら設定でONにするだけの価値があります。

全結果表・コード・再現手順はこちら。Apache-2.0。
https://github.com/genai-craft/openvons/tree/main/docs/jevpick
```

## 単発版 (272)
```
LLMの生成を、別モデルを学習せずに3〜5倍速にする方法。

次の数語の候補をツール定義から作り、モデル自身の内部状態で1つ選び、まとめて検算する。出力は1文字も変わらない。

ツール呼び出しで実測。4-bit量子化でも成立、長文脈では「先読みしない判断」が効く。
https://openvons.com/jevpick
```

## 英語版 (約 260)
```
openvons' idea — don't generate, pick from a finite menu — applied to LLM decoding itself.

JevPick: a menu of likely next tokens from the tool schema, the model's own hidden state picks one, verified in one pass. 3–5x faster tool calls, identical output, no draft model.
https://openvons.com/jevpick
```

補足: 「出力は1文字も変わりません」は greedy (温度 0) の話。突っ込まれたら「単精度で全 token 一致、半精度は丸め誤差の範囲」(記事の注釈と同じ)。
